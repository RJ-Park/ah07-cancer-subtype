### 우선순위 (시상 기준 반영)

상은 **리더보드 점수(90%)**로 정해지고, 코드 검증에서 한 번 걸리면 탈락이에요. 그래서 우선순위는 이렇게 가요.

1. **규정 통과:** 누수 없음, 재현 가능, 제출 형식. 팀장이 PR 리뷰와 최종 점검으로 책임져요.
2. **리더보드 점수:** 고성능 모델에 시간을 가장 많이 써요. ④의 경량 모델(로지스틱 회귀 등)도 **앙상블 재료**로 점수에 보태요.
3. **발표(10%):** 경량화 비교, 서비스 기획, 데이터 해석. 서비스 기획은 발표 몇 장 분량으로 가볍게 하고, 데이터 해석(EDA, 오분류)은 동점일 때 기준이 되니 챙겨요.

### 역할별 완료 기준

- **① 장성은:** 서비스 시나리오 1장, 제출 기록표, 누수 체크리스트 전 항목 확인, PPT 노션 제출, 코드 디스코드 제출
- **② 홍시윤:** 암종 분포·변이 분포 그래프, 피처 비교표(A 원본 인코딩 / B 이진화 / C B+변이 개수 / D C+변이 유형), 모델 담당에게 넘긴 관찰 3개 이상
- **③ 안주형:** 3개 모델 비교표, 앙상블 vs 단일 모델 비교, 모든 seed·하이퍼파라미터가 코드에 숫자로 적힘
- **④ 박유정:** 성능·속도·크기 비교표(실제 측정값만), 새 Colab 재현 성공, 모델 파일 다운로드 링크

## 4. 협업 규칙

1. **작업마다 새 브랜치(`feat/역할_성이니셜_월일`)를 만들고, 자기 폴더만 수정**해요. `.ipynb`는 둘이 같은 파일을 고치면 합칠 수 없어요.
2. **dev에는 PR로만** 합쳐요. 본인 말고 팀원 1명이 PR 템플릿의 누수 체크리스트를 보고 승인해요. 애매하면 팀장에게 넘겨요. `main`에는 최종본만 팀장이 합쳐요.
3. **`src/`는 담당자만 수정**하고, 바꾸면 디스코드에 알려요.
4. **피처는 검증된 것만** `src/features.py`로 옮겨요 (`run_cv()` 점수가 오른 것만). 피처 선택은 전체 데이터가 아니라 fold의 학습 부분에서만 해요.
5. 실험 결과는 `log_result()`로 **자기 기록표**(`experiments/log_J_leader.csv` 등 폴더 이름과 같은 파일)에 남겨요.
6. 제출하고 싶은 후보는 **CV 점수와 함께 팀장에게** 알려요.
7. 코드는 어떻게 짜든 **`docs/coding_rules.md`(팀 코딩 규칙)를 지켜요.** train과 test를 합치는 코드는 쓰지 않아요. AI 도구를 쓴다면 문서 끝의 요약을 활용해도 돼요(선택).
8. 이전 대회(특히 2024년 같은 주제 대회)나 공개 코드는 참고하지 않아요. 외부 데이터는 쓰지 않아요.
